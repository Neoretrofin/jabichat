# План разработки проекта: jabichat 🐸

**Контекст для ИИ-ассистента:**
Ты — Senior Web Developer. Наша цель — разработать серверлес-мессенджер (PWA) под названием **jabichat**. Архитектура полностью децентрализованная:
1. **База данных и сигналинг:** Сеть Nostr (используем публичные реле).
2. **Шифрование:** NIP-44 / NIP-17 для личных сообщений (E2EE).
3. **Звонки и трансляция экрана:** WebRTC (P2P), где Nostr используется в качестве сигнального сервера (через эфемерные события/ephemeral events).
4. **Стиль интерфейса:** "Жабки" (Toad/Frog theme) — болотные, зеленые тона, элементы в виде кувшинок, уютная атмосфера.

---

## 🛠 Стек технологий (Tech Stack)
* **Frontend:** React + TypeScript + Vite.
* **Стилизация:** Tailwind CSS (для быстрой настройки "жабьей" палитры) + Lucide React (для иконок).
* **Nostr:** `@nostr-dev-kit/ndk` (NDK) — основная библиотека для работы с протоколом.
* **Стейт-менеджмент:** `zustand` (для хранения ключей, списка контактов и состояния звонка).
* **Маршрутизация:** `react-router-dom`.
* **PWA:** `vite-plugin-pwa` (для установки на телефон).

---

## 🎨 Дизайн-система (Toad Theme)
В `tailwind.config.js` нужно будет настроить следующие цвета:
* `swamp-dark`: Темно-болотный (фон приложения) - `#1e293b` или `#1c2e26`.
* `lily-green`: Светло-зеленый (для плашек сообщений) - `#4ade80` или `#86efac`.
* `frog-skin`: Насыщенный зеленый (основные кнопки) - `#22c55e`.
* `mud-brown`: Коричневый/земляной (дополнительные акценты, границы) - `#78350f` или `#451a03`.
* **Формы:** Максимальное скругление (`rounded-2xl`, `rounded-full`), чтобы элементы напоминали листья кувшинок (lily pads).

## 🚀 Пошаговый план разработки (Phases)

### Phase 1: Инициализация и Базовый UI
1. Инициализировать Vite React TS проект.
2. Установить Tailwind CSS, настроить "жабью" палитру (Toad Theme).
3. Настроить `vite-plugin-pwa` для генерации manifest.json (имя: jabichat, иконки в виде жабки).
4. Создать базовый Layout приложения (Bottom Navigation для мобилок: Чаты, Звонки, Профиль).

### Phase 2: Криптография и Аккаунты (Nostr)
1. Установить `ndk`.
2. Создать страницу входа/регистрации (Login/Signup Screen):
   * Кнопка "Создать жабку" (Генерация `nsec` и `npub`).
   * Поле "Войти по ключу" (Ввод существующего `nsec`).
3. Настроить безопасное сохранение `nsec` в `localStorage` браузера.
4. Настроить глобальный стейт (`zustand`): инициализация NDK, подключение к 3-4 дефолтным реле (например, `wss://relay.damus.io`, `wss://nos.lol`).

### Phase 3: Личные сообщения (Текст)
1. Разработать UI списка контактов.
2. Реализовать функционал "Добавить друга по npub".
3. Реализовать экран чата (Chat Screen) в стиле мессенджера (свои сообщения справа, чужие слева на фоне зеленых "кувшинок").
4. Интегрировать шифрование **NIP-44**: отправка и получение зашифрованных сообщений.
5. Настроить подписку (NDK Subscriptions) на входящие сообщения в реальном времени.

### Phase 4: Групповые чаты
1. Изучить и внедрить **NIP-28** (Публичные чаты) ИЛИ логику рассылки зашифрованных сообщений списку получателей (приватные группы).
2. Создать UI для создания "Ква-группы" (добавление нескольких `npub`).
3. Реализовать ленту группового чата.

### Phase 5: WebRTC Сигналинг через Nostr
1. Создать логику WebRTC-соединения (`RTCPeerConnection`).
2. Настроить передачу SDP (offer/answer) и ICE-кандидатов через **Эфемерные события Nostr (NIP-16/Ephemeral Events)**.
   * *Логика:* Приложение Алисы шифрует SDP и отправляет как эфемерное событие Бобу. Приложение Боба ловит его и отвечает своим SDP.

### Phase 6: Звонки и Трансляция экрана (WebRTC Media)
1. Создать UI для экрана звонка (Call Screen).
2. Запросить доступ к микрофону и камере (`navigator.mediaDevices.getUserMedia`).
3. Подключить MediaStream к `RTCPeerConnection`.
4. Реализовать кнопку "Поделиться экраном" (`navigator.mediaDevices.getDisplayMedia`), которая заменяет текущий видеотрек в P2P-соединении.
5. Добавить забавные элементы (например, звук кваканья "Ква!" при входящем звонке).

### Phase 7: Полировка и Деплой
1. Проверить работу приложения в офлайне (кэширование через Service Worker).
2. Добавить возможность экспорта ключа (чтобы пользователь не потерял аккаунт).
3. Подготовить проект к деплою на Vercel или GitHub Pages.
